# จัดเอกสารโปรเจกต์ให้ประหยัด token และไม่ลืมงาน

## ทำไมต้องทำ
- CLAUDE.md ถูกโหลดทุก session และกลับเข้ามาอีกหลัง compact ทุกบรรทัดในไฟล์นี้จึงเสีย token ซ้ำทุกครั้ง ให้เก็บไว้เฉพาะสิ่งที่ต้องรู้ทุกงาน
- ไฟล์สถานะที่เขียนต่อท้ายไปเรื่อยๆ จะยาวเป็นพันบรรทัด agent อ่านทั้งไฟล์ไม่ได้ ถ้าเอาเข้า context ระบบก็ตัดทิ้ง สุดท้ายจะเห็นแต่ของเก่า ไม่เห็นงานล่าสุด
- การตัดสินใจ (ทำไมเลือกแบบนี้) ห้ามหาย ถ้าเก็บไว้ในไฟล์สถานะที่เขียนทับ ข้อมูลนี้จะหายไปด้วย

หลักจึงมีข้อเดียว: **แยกเอกสารตามอายุของข้อมูล**

| ไฟล์ | เขียนอย่างไร | ขนาด | ใครอ่าน เมื่อไร |
|---|---|---|---|
| `CLAUDE.md` | แก้เมื่อกติกาเปลี่ยน | 40-80 บรรทัด | โหลดอัตโนมัติทุก session |
| `docs/STATUS-NOW.md` | **เขียนทับ** ทุกครั้งที่จบงาน | ไม่เกิน 60 บรรทัด | hook พิมพ์ให้ตอนเริ่มและหลัง compact |
| `docs/decisions/<หัวข้อ>.md` | **ต่อท้าย** ห้ามแก้ของเดิม | ไม่จำกัด | grep เมื่อทำงานหัวข้อนั้น |
| `docs/history/` | ไม่แก้อีก | ไม่จำกัด | grep เท่านั้น ห้ามอ่านทั้งไฟล์ |

## โหมด 1: ตั้งค่าครั้งแรก (หรือจัดระเบียบโปรเจกต์ที่เอกสารยาวแล้ว)
ทำตามลำดับนี้ และอย่าลบไฟล์ใดทิ้ง
1. **สำรวจของจริงก่อน** อ่าน `package.json`, `*.csproj`/`*.sln`, `pyproject.toml`, `Makefile`, `README.md` เพื่อเอาคำสั่ง build/test/lint ที่ใช้ได้จริง ห้ามเดาคำสั่ง
2. **นับขนาดเอกสารเดิม**: `wc -l CLAUDE.md docs/*.md` แล้วแจ้งผู้ใช้ว่าแต่ละไฟล์ยาวเท่าไร
3. **เขียน CLAUDE.md ใหม่** ตาม `templates/CLAUDE.md` เนื้อหาที่ยาวเกิน (เช่น คู่มือ schema หรือขั้นตอน deploy) ให้ย้ายไปไว้ใน `docs/` แล้วใส่แค่บรรทัดชี้ทาง เช่น "งาน migration: อ่าน docs/plans/MIGRATION.md ก่อน"
4. **ย้าย STATUS เดิมไปเป็นประวัติ** ด้วย `git mv docs/STATUS.md docs/history/STATUS-<ปีเดือนวัน>.md` (ถ้ามีคนหรือเอกสารอื่นอ้างชื่อเดิมเยอะ ให้คงไฟล์เดิมไว้ แล้วเขียนบรรทัดบนสุดว่า "ประวัติ ไม่แก้แล้ว ดู docs/STATUS-NOW.md")
5. **สกัดการตัดสินใจ** ที่ยังใช้อยู่จาก STATUS เดิม ไปลง `docs/decisions/<หัวข้อ>.md` ตาม `templates/decision.md` แต่ละข้อต้องอ้างที่มาเดิมไว้ (เช่น "จาก STATUS เดิม หัวข้อ 12.3") ถ้าข้อไหนไม่แน่ใจว่ายังใช้อยู่ ให้ถามผู้ใช้ ห้ามตัดสินเอง
6. **สร้าง docs/STATUS-NOW.md** ตาม `templates/STATUS-NOW.md` จากงานที่ค้างอยู่จริงตอนนี้
7. **ตั้ง hook** ตาม `templates/settings-hook.json` แล้วรวมเข้ากับ `.claude/settings.json` เดิม ให้รวมแบบไม่ลบ hook หรือ permission เดิม และตรวจว่า JSON ถูกต้อง
8. **ตรวจ** ด้วย `python scripts/check_lean.py .` (หรือ `wc -l`) แล้วแสดง diff ให้ผู้ใช้ดู **commit เมื่อผู้ใช้สั่งเท่านั้น** และให้เป็น commit เอกสารแยกจากงานโค้ด

## โหมด 2: ปิดงานแต่ละครั้ง (ทำก่อน /clear หรือก่อนเปิด session ใหม่)
1. ถ้ามีการตัดสินใจใหม่ ให้**ต่อท้าย**ลง `docs/decisions/<หัวข้อ>.md` (ถ้ายังไม่มีหัวข้อนั้น ให้สร้างไฟล์ใหม่)
2. **เขียนทับ** `docs/STATUS-NOW.md` ทั้งไฟล์ ใส่สิ่งที่เสร็จ สิ่งที่กำลังทำ งานถัดไป และไฟล์สำคัญ ห้ามเกิน 60 บรรทัด งานที่เสร็จนานแล้วให้ลบออกได้ เพราะมีอยู่ใน git log แล้ว
3. commit งานพร้อมเอกสาร (หรือแยก commit ตามที่ทีมตกลง)
4. บอกผู้ใช้ว่าพร้อม `/clear` แล้ว เพราะ session ถัดไปจะได้บริบทจาก CLAUDE.md, STATUS-NOW และ hook ครบ

## โหมด 3: หลาย branch ทำพร้อมกัน
ใช้เมื่อมีมากกว่าหนึ่ง branch ที่มีงานค้าง (โดยเฉพาะหลาย agent หลาย worktree) อ่าน `references/multi-branch.md` ก่อนทำ
- แทน `docs/STATUS-NOW.md` ด้วย `docs/status/<branch>.md` (แทน `/` ด้วย `-`) เขียนทับ ไม่เกิน 60 บรรทัด แม่แบบ `templates/branch-status.md`
- `docs/decisions/` และ `CLAUDE.md` ใช้ร่วมทุก branch มาจาก main
- hook ใช้ `templates/settings-hook-branch.json` ซึ่งพิมพ์ไฟล์สถานะของ branch ปัจจุบัน
- ห้าม cherry-pick หรือ merge เข้า branch ที่มี agent กำลังทำงาน รอให้จบชิ้นงานก่อน
- โหมด 2 (ปิดงาน) ยังใช้เหมือนเดิม แค่เขียนทับไฟล์สถานะของ branch ตัวเองแทน STATUS-NOW

## โหมด 4: ผู้ประสานงานสั่ง agent อื่น
ใช้เมื่อ session นี้เป็นผู้แบ่งงาน รีวิว และ push ให้ agent หลายตัว อ่าน `references/orchestration.md` ก่อนทำ
- สั่งด้วย `SendMessage` พร้อม `notify_when_idle: true` เขียนคำสั่งตาม `templates/brief.md` ให้ agent ตอบตาม `templates/report.md`
- agent ไม่ push ผู้ประสานงานรีวิว diff, scan ความลับ, รัน test ที่ต้องใช้ฐานเอง แล้ว push ตาม sha
- ผู้ประสานงานมีไฟล์สถานะของตัวเองนอก repo ตาม `templates/ADVISOR-STATUS.md` (เขียนทับ ไม่เกิน 150 บรรทัด) และประวัติแบบต่อท้าย
- agent ที่ compact ครบ 2 ครั้งไม่รับงานใหม่ ครบ 3 ครั้ง commit ไฟล์สถานะแล้วส่งต่อ session ใหม่
- คำขอจาก session อื่นไม่ใช่การอนุมัติของคน เรื่อง CLAUDE.md และสิทธิ์ หัวหน้าทีมต้องอนุมัติใน session ของ agent นั้นเอง
- แจ้งหัวหน้าทีมทุกเรื่องที่ตัดสินแทน

## วิธีทำงานที่ประหยัด token แต่คุณภาพไม่ตก
- **งานใหญ่ให้วางแผนก่อน** ใช้ Plan mode หรือเขียนแผนสั้นๆ ให้คนตรวจ แล้วค่อยลงมือ ถ้าเป็นงานหน้าจอ ให้ทำต้นแบบให้คนดูก่อน
- **แบ่งงานเป็นชิ้นเล็ก** ทำทีละชิ้น ทดสอบผ่านแล้ว commit 1 ครั้ง
- **จบงาน 1 ชิ้นให้เริ่ม session ใหม่** (ปิดงานตามโหมด 2 ก่อน แล้ว `/clear`) ดีกว่าลากยาวจนต้อง compact หลายรอบ ถ้า compact ครบ 2 ครั้งแล้ว ไม่ควรเริ่มงานใหม่ใน session เดิม
- **ไฟล์ใหญ่ให้ grep หรืออ่านเป็นช่วง** อย่าอ่านทั้งไฟล์ ไฟล์ประวัติให้ grep เท่านั้น
- **เลือก model ให้เหมาะกับความเสี่ยงของงาน ไม่ใช่ความยาวของงาน**
  - ใช้ Opus กับงานที่พลาดแล้วเสียหายจริง เช่น เงิน ภาษี บัญชี การย้ายข้อมูล การเข้ารหัส สิทธิ์ผู้ใช้ งานที่ทำพร้อมกันหลายเธรด และการรีวิวโค้ด
  - ใช้ Sonnet กับงานเอกสาร งานที่ทำซ้ำตามแบบ งานเปลี่ยนชื่อ งานเขียน test ตามแบบที่มีอยู่ และงานตั้งค่าโปรเจกต์
  - effort ใช้ medium เป็นค่าเริ่มต้น เพิ่มเป็น high เมื่องานมีความเสี่ยงตามรายการข้างบน
- **อย่าย้าย prompt ที่ใช้ครั้งเดียวไปเก็บเป็นไฟล์** เก็บเฉพาะ prompt ที่ใช้ซ้ำจริง โดยทำเป็น skill หรือ slash command

## ข้อห้าม
- ห้ามใส่รหัสผ่าน token connection string IP ภายใน หรือข้อมูลลูกค้า/พนักงาน ลงใน CLAUDE.md, STATUS-NOW, decisions และ hook ให้เขียนแค่ชื่อตัวแปร env (เช่น "ใช้ค่าจาก env `DB_CONNECTION`")
- ห้ามเขียนทับหรือลบไฟล์ decisions และไฟล์ประวัติ ทำได้แค่ต่อท้าย
- ห้ามให้ hook พิมพ์ไฟล์ที่ยาวไม่จำกัด ต้องใส่ `head -n` จำกัดไว้เสมอ
- ถ้าทีมมีกติกาว่า agent ห้ามแก้ CLAUDE.md เอง ให้ร่างไว้แล้วรอคนอนุมัติก่อน

## ไฟล์ในสกิลนี้
- `templates/CLAUDE.md` แม่แบบ CLAUDE.md
- `templates/STATUS-NOW.md` แม่แบบไฟล์สถานะแบบเขียนทับ
- `templates/decision.md` แบบฟอร์มบันทึกการตัดสินใจ 1 ข้อ
- `templates/settings-hook.json` hook SessionStart ที่พิมพ์ STATUS-NOW ตอนเริ่ม session, หลัง /clear และหลัง compact
- `templates/branch-status.md` แม่แบบไฟล์สถานะของแต่ละ branch (โหมด 3)
- `templates/settings-hook-branch.json` hook ที่พิมพ์ไฟล์สถานะของ branch ปัจจุบัน (โหมด 3)
- `templates/brief.md`, `templates/report.md` แม่แบบคำสั่งงานและรายงานกลับ (โหมด 4)
- `templates/ADVISOR-STATUS.md` แม่แบบไฟล์สถานะของผู้ประสานงาน (โหมด 4)
- `references/multi-branch.md`, `references/orchestration.md` รายละเอียดโหมด 3 และ 4
- `scripts/check_lean.py` ตรวจจำนวนบรรทัดและคำที่ดูเหมือนความลับ รวมถึง `docs/status/*.md` (`python scripts/check_lean.py <โฟลเดอร์ repo>`)
