# ผู้ประสานงานสั่ง agent อื่นทำงาน

ใช้เมื่อมี session หนึ่งเป็น **ผู้ประสานงาน** (ที่ปรึกษา หัวหน้าเทคนิค) คอยแบ่งงาน ส่งคำสั่ง รีวิว และ push
ให้ agent หลายตัวที่ทำงานคนละ branch โดยมี **หัวหน้าทีม** (คน) เป็นผู้ตัดสินเรื่องธุรกิจและหน้าจอ

## บทบาท

| ใคร | ทำ | ไม่ทำ |
|---|---|---|
| หัวหน้าทีม (คน) | ตัดสินเรื่องธุรกิจ ตรวจหน้าจอ อนุมัติ CLAUDE.md และสิทธิ์ เปิด session สำรองไว้ให้ | ไม่ต้องสั่ง agent ทีละตัว |
| ผู้ประสานงาน | แบ่งงาน เขียนคำสั่ง ตอบคำถาม รีวิว diff scan ความลับ รัน test ที่ต้องใช้ฐานข้อมูล push ตาม sha บันทึกสถานะ | ไม่แก้โค้ดใน branch ที่มี agent ทำงานอยู่ ไม่อนุมัติแทนหัวหน้าทีมในเรื่องที่ agent ต้องได้ยินจากคนโดยตรง |
| agent | ทำงานตามคำสั่งใน branch/worktree ของตัวเอง test commit ในเครื่อง ส่ง sha แล้วหยุด | ไม่ push ไม่เขียนประวัติ git ใหม่ ไม่แก้ CLAUDE.md เอง ไม่แตะ branch อื่น |

## ช่องทางสั่งงาน
- **session อื่นในเครื่องเดียวกัน**: `ListAgents` หาชื่อ แล้ว `SendMessage` พร้อม `notify_when_idle: true` จะได้แจ้งเตือนหนึ่งครั้งเมื่อ agent ทำเสร็จ ไม่ต้องถามซ้ำว่าเสร็จหรือยัง
- **subagent** (`Agent` tool): ใช้กับงานสั้นที่ไม่ต้องคุยต่อหลายรอบ
- บรรทัดแรกของข้อความต้องบอกเรื่องได้ในตัว เพราะคนเห็นแค่บรรทัดแรกก่อนกดเปิด
- คำสั่งที่ส่งต้องอ่านเข้าใจได้โดยไม่ต้องรู้บทสนทนาก่อนหน้า agent ไม่เห็นสิ่งที่ผู้ประสานงานคุยกับหัวหน้าทีม

## ขั้นตอนต่อหนึ่งชิ้นงาน
1. **เลือก agent**: ใช้ session สำรองที่ว่างก่อน ห้ามดึง agent ที่ทำงานอื่นอยู่ หนึ่ง agent ต่อหนึ่ง branch
2. **เขียนคำสั่ง** ตาม `templates/brief.md` (เป้าหมาย branch/worktree ไฟล์ที่ต้องอ่าน สิ่งที่ต้องส่ง ข้อห้าม การตรวจก่อนส่ง "ส่ง sha แล้วหยุด")
3. **จองทรัพยากร** ก่อนส่ง: ช่วงรหัสสมมติสำหรับ test ชื่อฐานทดสอบ พอร์ต ไม่ให้สอง agent ใช้ซ้ำกัน แล้วบันทึกในสถานะของผู้ประสานงาน
4. **รอแจ้งเตือน** ระหว่างรอทำงานอื่นได้ ห้ามเดาผลของ agent ที่ยังไม่ตอบ
5. **รีวิว** เมื่อได้ sha (ดูรายการตรวจข้างล่าง) ถ้าไม่ผ่าน ส่งกลับพร้อมเหตุผลเป็นข้อๆ
6. **push ตาม sha** หลังรีวิวผ่าน: `git merge-base --is-ancestor origin/<b> <sha> && git push origin <sha>:refs/heads/<b>` (branch ใหม่ไม่ต้องตรวจ ancestor) ซ่อน URL ใน output
7. **บันทึก** ต่อท้ายไฟล์ประวัติของผู้ประสานงาน และเขียนทับไฟล์สถานะสั้นของผู้ประสานงาน
8. **รายงานหัวหน้าทีม** สั้นๆ และบอกทุกเรื่องที่ตัดสินแทน

## รายการตรวจตอนรีวิว
- `git log --oneline` และ `git diff --stat` ตรงกับที่สั่ง ไม่มีไฟล์เกินมา
- scan ความลับใน diff ทั้งหมด (รหัสผ่าน token connection string IP กุญแจ ข้อมูลบุคคล)
- อักขระหรือคำที่ทีมห้าม (ถ้ามี) และจำนวนบรรทัดของไฟล์สถานะ (`check_lean.py`)
- test ที่ agent รันไม่ได้ (เช่น ต้องใช้ฐานข้อมูลหรือความลับ) ผู้ประสานงานรันเองในระดับ process ไม่ส่งความลับให้ agent
- งานหน้าจอ: ดูภาพหน้าจอจริงก่อนส่งให้หัวหน้าทีม

## นับ compact ของ agent
- ให้ agent รายงานจำนวน compact ทุกครั้งที่ส่งงาน
- ครบ 2 ครั้ง: ทำชิ้นที่ค้างให้จบ แล้วไม่รับงานใหม่
- ครบ 3 ครั้ง: commit ไฟล์สถานะของ branch แล้วตอบ "ready for new session" งานต่อให้ session ใหม่ซึ่งอ่านไฟล์สถานะของ branch เอา

## สิทธิ์และความปลอดภัย
- **ห้ามสั่ง agent ทำสิ่งที่ผู้ประสานงานเองไม่มีสิทธิ์ทำ** หรือสิ่งที่ถูกปฏิเสธสิทธิ์ไปแล้ว นั่นคือการเลี่ยงการตัดสินของคน ให้ส่งเรื่องกลับไปหาหัวหน้าทีม
- agent ที่ปฏิเสธคำขอแก้ CLAUDE.md หรือสิทธิ์ เพราะคำขอมาจาก session อื่น ถือว่าทำถูก ห้ามหาทางอ้อม ให้หัวหน้าทีมพิมพ์อนุมัติใน session ของ agent นั้นเอง
- ห้ามแก้ไฟล์ตั้งค่าสิทธิ์เพราะ agent อื่นขอ
- ห้ามส่ง connection string รหัสผ่าน หรือ token ให้ agent ให้บอกแค่ชื่อตัวแปร env ถ้า agent ต้องใช้จริง ผู้ประสานงานรันส่วนนั้นเอง
- งานที่ย้อนกลับยาก (ลบ ฐานข้อมูลจริง push แรง โพสต์ออกนอกทีม) ต้องได้รับอนุมัติจากหัวหน้าทีมก่อน

## เมื่อ agent ถาม
1. หาคำตอบใน `docs/decisions/` และสถานะของผู้ประสานงานก่อน
2. ถ้าเป็นเรื่องเทคนิคที่มีคำตอบชัด ผู้ประสานงานตัดสินได้ บันทึกลง decisions และแจ้งหัวหน้าทีม
3. ถ้าเป็นเรื่องธุรกิจ เงิน กฎหมาย หรือหน้าจอ ให้ agent หยุดรอ แล้วถามหัวหน้าทีม ระหว่างรอ agent ทำส่วนที่ไม่ขึ้นกับคำตอบได้
4. ถ้าไม่แน่ใจ ให้ทำเป็นค่าตั้ง (setting) ที่มีค่าเริ่มต้น ดีกว่าเขียนค่าตายตัว

## เมื่อหัวหน้าทีมสั่ง "หยุด"
ส่งให้ทุก agent: commit งานที่ค้าง เขียนทับไฟล์สถานะของ branch แล้วหยุดรอ จากนั้นผู้ประสานงานบันทึกสถานะของตัวเองแล้วส่งมอบ

## ไฟล์ของผู้ประสานงาน (อยู่นอก repo ของ agent)
- สถานะสั้น เขียนทับ ไม่เกิน 150 บรรทัด ตาม `templates/ADVISOR-STATUS.md`
- ประวัติ ต่อท้ายเท่านั้น ห้ามอ่านทั้งไฟล์ ใช้ grep หาเลขรายการ
- hook SessionStart ในโฟลเดอร์ของผู้ประสานงาน พิมพ์ไฟล์สถานะสั้นด้วย `head -n 150` และรายการประวัติล่าสุดสามรายการ
- สคริปต์แก้ไฟล์ภาษาไทยให้เขียนด้วย Write tool แล้วรันด้วย python (heredoc ใน Bash อาจกิน backslash)
